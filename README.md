# LeadBoard

Общий сервис таблиц лидеров для нескольких игр: PHP API, MySQL и сайт на React.
Сервис сохраняет все попытки и возвращает лучший результат каждого игрока для выбранной игры и режима.

**[Примеры подключения игр →](examples.md)**

## Быстрое подключение

1. Добавьте игру в таблицу `games`.
2. После завершения попытки отправьте результат в `POST add.php`.
3. Для рейтинга вызовите `POST getTop.php` с той же игрой и режимом.
4. Укажите `order: "DESC"`, если больше — лучше, или `order: "ASC"`, если меньше — лучше.

Базовый адрес в примерах:

```text
https://gagikpog.ru/leadboard/
```

Описание соответствует файлам в репозитории. Для использования новых возможностей эти PHP-файлы должны быть загружены на сервер.

## Как устроен рейтинг

| Понятие | Поле | Пример |
| --- | --- | --- |
| Игра | `game` | `calendar`, `minesweeper` |
| Режим внутри игры | `mode` | `default`, `beginner`, `intermediate`, `advanced` |
| Игрок внутри игры и режима | `identifier` | Имя или постоянный ID |
| Результат попытки | `score` | Очки или время в целых секундах |
| Дополнительные данные | `meta` | JSON-строка с именем, изображением и другими данными |

- Каждое сохранение создаёт новую попытку. Повторный запрос создаст ещё одну запись.
- Рейтинг разделён по `game` и `mode`. Отсутствующий `mode` означает только `default`, а не все режимы.
- В рейтинге возвращается одна лучшая попытка на `identifier`.
- При `ASC` выбирается минимальный результат, при `DESC` — максимальный.
- При равных результатах выбирается более ранняя попытка, затем запись с меньшим ID.
- Игроки с одинаковым результатом также упорядочиваются по дате, затем ID.
- Дата и `meta` принадлежат выбранной попытке. Дату новой попытки назначает сервер БД.
- Направление рейтинга задаёт клиент при чтении. В таблице `games` оно не хранится.
- `identifier` — переданный клиентом идентификатор, а не авторизация пользователя.

Для календаря используется `mode: "default"`, `order: "DESC"`. Для сапёра — режим сложности и `order: "ASC"`.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `getGames.php` | Список зарегистрированных игр |
| `POST` | `add.php` | Сохранение попытки |
| `POST` | `getTop.php` | Лучшие результаты игроков |

POST-запросы передают JSON в теле. Ответы имеют `Content-Type: application/json; charset=utf-8`.
Токен авторизации текущим API не требуется.

### Список игр — `GET getGames.php`

Параметры не нужны. Игры читаются из `games` и сортируются по `name`.

```json
{
  "status": "done",
  "message": "Список игр получен.",
  "data": [
    { "id": "calendar", "name": "Flappy Calendar" },
    { "id": "minesweeper", "name": "Сапёр" }
  ]
}
```

Список не содержит режимов и правил сортировки: клиент определяет их для своей игры.

### Сохранение — `POST add.php`

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `identifier` | string | Да | Постоянный ID или имя игрока, до 50 символов по схеме БД |
| `score` | integer | Да | Целочисленный результат; текущий обработчик отклоняет `0` |
| `game` | string | Да | Существующий `games.id` |
| `mode` | string | Нет | Непустая строка до 50 байт; по умолчанию `default` |
| `meta` | string | Нет | JSON, сериализованный в строку; по умолчанию `"{}"` |

Передавайте `meta` как `JSON.stringify({...})`, а не как объект. Содержимое JSON в `meta` сервер не проверяет.
Режим не сверяется со справочником: список допустимых режимов определяет игра.
Не используйте пустой идентификатор или строку `"0"`: текущая проверка PHP их отклоняет.

```json
{
  "identifier": "gagikpog",
  "score": 120,
  "game": "minesweeper",
  "mode": "advanced",
  "meta": "{}"
}
```

Успешный ответ не содержит `data` или ID созданной записи:

```json
{
  "status": "done",
  "message": "Результат успешно сохранен."
}
```

### Чтение рейтинга — `POST getTop.php`

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `game` | string | Да | Существующий `games.id` |
| `mode` | string | Нет | Непустая строка до 50 байт; по умолчанию `default` |
| `order` | string | Нет | Строго `ASC` или `DESC`; по умолчанию `DESC` |
| `limit` | integer | Нет | Число игроков; по умолчанию `10` |

Передавайте положительный целый `limit`. Сейчас числовое значение приводится к целому и ограничивается снизу единицей; нечисловое заменяется на `10`.

```json
{
  "game": "minesweeper",
  "mode": "advanced",
  "order": "ASC",
  "limit": 10
}
```

Пример ответа:

```json
{
  "status": "done",
  "message": "Результат успешно поучен.",
  "data": [
    {
      "identifier": "gagikpog",
      "score": "120",
      "date": "2026-10-31 12:00:00",
      "meta": "{}"
    }
  ]
}
```

`score` может приходить строкой или числом в зависимости от PDO; используйте `Number(item.score)`.
`meta` — строка, у старых записей возможен `null`; разбирайте её с обработкой ошибок.
`date` имеет формат `YYYY-MM-DD HH:mm:ss`, без часового пояса. API не выполняет преобразование даты в UTC.
Если результатов нет, возвращается `status: "done"` и `data: []`.

### Обработка ошибок

```json
{
  "status": "error",
  "message": "Игра указанна неверно!"
}
```

Проверяйте и HTTP-статус, и `status` в JSON. Не используйте текст `message` как код ошибки.

| Ситуация | Текущее поведение |
| --- | --- |
| Успешный запрос | HTTP `200`, `status: "done"` |
| Неизвестная игра или часть ошибок сохранения | HTTP `200`, `status: "error"` |
| Некорректный `mode` или `order` | HTTP `400`, `status: "error"` |
| Неверный метод для `add.php` / `getTop.php` | HTTP `400`, пустое тело |
| Неверный метод для `getGames.php` | HTTP `405`, `status: "error"` |
| Ошибка подключения или запроса к БД | HTTP `500`, `status: "error"` |

Всегда отправляйте корректный JSON-объект с обязательными полями: обработка повреждённого JSON и отсутствующих полей пока не унифицирована.

### Запросы из браузера

API разрешает чтение с других доменов через CORS, но отдельной обработки `OPTIONS` сейчас нет.
Для междоменных POST-запросов используйте `Content-Type: text/plain;charset=UTF-8` с JSON в теле, как в [примерах](examples.md).
PHP читает тело напрямую, поэтому этот формат поддерживается. Заголовок `application/json` при запросе с другого домена запускает предварительный запрос `OPTIONS`, который текущие обработчики не обслуживают.

## Добавление новой игры

Выполните в своей БД, подставив код и название игры:

```sql
INSERT INTO `games` (`id`, `name`)
VALUES ('new-game', 'Новая игра');
```

Код игры должен быть уникальным и помещаться в `VARCHAR(20)`. API начнёт принимать этот `game` без изменения PHP.
Внешний ключ связывает `board.game` с `games.id`: зарегистрируйте игру до сохранения результатов.

Клиент игры определяет идентификатор игрока, единицу результата, режимы и направление рейтинга.
На сайте LeadBoard новые игры появляются в списке автоматически; по умолчанию отображаются `identifier`, очки и режим `default`.
Выбор сложностей сейчас реализован отдельно для сапёра. Для нестандартного отображения или режимов другой игры потребуется обновить интерфейс сайта.

## Структура проекта

| Файл / каталог | Назначение |
| --- | --- |
| `add.php`, `getTop.php`, `getGames.php` | HTTP API |
| `utility.php` | Работа с БД и общие заголовки |
| `pass.php` | Настройки подключения, функция `getMySQLAuthData()` |
| `db.sql` | Создание таблиц `games`, `board` и связи между ними |
| `src/` | React-интерфейс таблиц лидеров |
| `examples.md` | Готовые примеры JavaScript для подключения игр |
| `import-minesweeper.sql` | Одноразовый импорт исторических попыток сапёра |

`db.sql` предназначен для создания таблиц в уже существующей БД `k992302t_board`; это не скрипт обновления существующей структуры и он не заполняет `games`.
Импорт сапёра уже выполнен; повторное выполнение `import-minesweeper.sql` создаст дубликаты.

## Разработка и размещение

Требуются Node.js/npm для интерфейса и сервер с PHP, PDO MySQL и MySQL/InnoDB для API.

```bash
npm install
npm run dev
```

Интерфейс открывается на `http://localhost:3000`. Сервер разработки React не исполняет PHP; API запускается отдельно.
Адрес API для интерфейса указан в `src/App.tsx`.

Сборка интерфейса:

```bash
npm run build
```

Для размещения загрузите содержимое `build/` и PHP-файлы API в каталог сайта.
Настройте подключение к MySQL через `getMySQLAuthData()` в `pass.php`: `serverName`, `username`, `password`, `dbname`.
SQL-дампы и файлы импорта не нужно размещать в публичном каталоге сайта.

The build is minified and the filenames include the hashes.\
Your app is ready to be deployed!
